Agent Tooling Landscape

Everyone building in this space right now is solving one of four problems: installing MCP servers, distributing skills, keeping rules consistent across agents, or governing all of it for an org. Almost nobody is doing what Agent Tooling does — treating a personal machine's agent setup as reviewable, receipted, desired state.

Closest to what you are building

These are the ones to actually look at. Each overlaps on a different axis: GUI, multi-client install, or machine-to-machine sync.

skills-manager closest overall 4,335★

A Tauri desktop app plus a CLI sharing one SQLite engine, managing and deploying skills across 50+ tools. The part worth studying: git-backed sync to any private remote, with skill-aware merge, conflict resolution, and restorable snapshots. That is the multi-machine story you are building toward with encrypted folder sync, solved a different way.

Pushed today. Created March 2026 and already the most-starred thing in this category.

SkillDock 504★

Desktop control center that scans real project directories and installs, organizes, syncs, and updates skills, MCP servers, and plugins across Claude Code, Cursor, Codex, Windsurf, and Gemini CLI — with git-aware diffs. Closest to your screen-by-screen scope, and it covers project directories, which is the thing you handle with project scope.

Claude Code Tool Manager 379★

Tauri + Svelte GUI to see and toggle MCP servers, commands, skills, sub-agents, and hooks per project for Claude Code. Single-client where you are three-client, but the per-project toggling model is worth comparing against your configurations.

tech-leads-club/agent-skills 5,110★

The strongest CLI competitor. Installs skills across 19 agents, runs Snyk security scanning before publishing, and tracks installs with a lockfile plus content hashes — which is essentially your reviewed source fingerprint, applied to updates. Their pitch cites 13% of marketplace skills carrying critical vulnerabilities.

Promptzy macOS, closed source

Native Mac menu-bar app calling itself the source of truth for AI skills, with multi-directional sync and conflict resolution across Claude, Cursor, Copilot, ChatGPT, Gemini, Windsurf. Free tier, $5 one-time Pro, and iCloud sync as the paid feature. The nearest thing to your product shape and positioning.

AgentSync brand new 1★

Snapshots Claude, Cursor, Codex, Copilot, VS Code, and OpenCode config, encrypts it with age recipients, and pushes to a per-machine namespace in a git-backed vault. Essentially your encrypted folder sync with a different key model. Unadopted so far, but the design is the closest match to your multi-Mac path.

Agent Plugins Specification 1,226★

Not a competitor — the standard your library already speaks. A cross-vendor packaging spec (plugin.json + skills/ + optional mcp.json) with a steering committee reported to include Amazon, Cursor, Microsoft, OpenAI, and Vercel, adopted by ChatGPT/Codex, Cursor, Copilot, Kiro, and VS Code. v1.1 is in draft. This is the one to track for interoperability.

Where this leaves you

Nobody else does these

  • Plan before change, with a digest. Across 70+ projects, not one shows a Terraform-style diff of exactly what will be written and refuses to run if the plan changed after review. The nearest is mcpm.sh's update --check, which only covers version bumps.
  • Receipts for one person. Audit logs exist only in the enterprise gateway tier — ToolHive, Obot, mcpmanager.ai — where they are a network product for an org. Nobody keeps a local, redacted, per-operation receipt on a personal machine.
  • Honest verification vocabulary. Observed versus Installed versus Authenticated, with the app refusing to infer the last one, appears to be unique. Everything else reports a single ambiguous "installed" state.
  • Per-client partial success. Configuring three clients independently and keeping the successes when one fails is not something the multi-client installers advertise.

Where others are ahead, and worth stealing

  • Git-backed sync with conflict resolution (skills-manager) is a friendlier multi-machine story than an encrypted blob, because you can see history and merge. Your Git backup is one commit away from this.
  • Lockfile plus content hashes (tech-leads-club/agent-skills) turns your reviewed-source fingerprint into an update mechanism: know when an installed skill drifted from the library.
  • Security scanning before install — Snyk in agent-skills, image signing in Docker's catalog, provenance in ToolHive. You already detect executable content; scanning is the next step.
  • Filter a catalog by source and by client. Cursor Directory and the VS Code gallery both do this and it is table stakes.
  • Containerized isolation (ToolHive, Docker) is the strongest answer to "should I trust this MCP server", and is orthogonal to everything you have built.
The honest summary. The GUI slot is contested — skills-manager and SkillDock are doing a version of your app, and Promptzy is doing your positioning on macOS. What none of them treat as the point is the review-and-receipt discipline. That is the thing to lead with, not "manage your skills".
